  ---
  PKCE flow

  1. User visits any protected route → redirected to /login
  2. User enters username + clicks Sign In → keycloak.login() redirects to
  Keycloak with code_challenge (S256 PKCE)
  3. Keycloak authenticates (its own page handles the password) → redirects back
   to /user?code=...
  4. keycloak-js detects the code, exchanges it for tokens using the
  code_verifier (PKCE)
  5. AuthProvider updates isAuthenticated = true → app renders /user
  6. If Keycloak returns ?error=... on redirect → the error message is shown on
  the login page

  ▎ Note: The username field is forwarded to Keycloak as login_hint. With 
  PKCE/Authorization Code flow, the password is entered on Keycloak's hosted 
  page — this is the security boundary. Update the three VITE_KEYCLOAK_* values 
  in .env to match your Keycloak server configuration, and ensure your Keycloak 
  client has http://localhost:5173/user in its valid redirect URIs.
